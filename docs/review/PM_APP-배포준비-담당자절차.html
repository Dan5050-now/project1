PM_APP 1.21.1 · 준비 담당자용

PM_APP 배포 준비 절차

담당자 PC의 어느 폴더에 무엇을 두고, 어떤 명령이 무엇을 읽어 무엇을 만들며, 공유 폴더의 어디에 놓는지. 한 사람이, 버전마다 한 번 하는 일입니다.

담당자 PC에 필요
Python 3.9 이상
사용자 PC에 필요
없음
최초 준비
30~40분
이후 버전마다
10~15분

이 문서는 담당자 한 사람을 위한 것입니다. 일반 사용자에게는 별도의 안내서가 있고, 그쪽에는 이 내용이 하나도 필요하지 않습니다 — 사용자가 할 일은 압축을 풀고 더블클릭하는 것뿐입니다.

파이썬은 담당자 PC에만 있으면 됩니다. 사용자 PC용 파이썬은 아래 3단계에서 앱 폴더 안에 넣어 배포하므로, 사용자는 설치도 내려받기도 하지 않습니다.

1담당자 PC 준비 — 최초 1회

1-1. src\ 와 tools\ 를 어디서 얻는가

하나의 압축본으로 옵니다. PRAP_source_src_tools.zip 안에 src\(앱의 소스)와 tools\(빌드·검증 도구)가 함께 들어 있고, 담당자에게 필요한 것은 이 파일 하나뿐입니다.

경로무엇을언제 쓰는가
① 기존 압축본 PRAP_source_src_tools.zip 가장 간단합니다. 이미 받으신 것이 있으면 그것으로 충분합니다
② 저장소에서 Dan5050-now/project1
브랜치 claude/project-

③ 직접 만들기 python tools\package_source.py 한 번이라도 ①이나 ②로 확보한 뒤부터. 다음 사람에게 넘길 압축본을 만드는 정식 방법입니다
닭과 달걀

압축본을 만드는 도구(package_source.py)가 tools\ 안에 있습니다. 그래서 맨 처음 한 번만 ①이나 ②로 받아야 하고, 그 뒤로는 ③이 정식 경로입니다.

③이 정식인 이유 — 스스로 검증합니다

package_source.py 는 압축본을 쓰기 전에 임시 폴더에 풀어서 실제로 빌드해 봅니다. 그 결과가 저장소의 app\PRAP.html 과 바이트 단위로 같지 않으면 아무것도 쓰지 않습니다. 빌드되지 않는 소스 묶음은 인도물이 아니라는 뜻이고, 그것을 따져 보는 대신 해 보는 쪽을 택한 것입니다.

1-2. 작업 폴더를 정하고 소스를 풉니다

어디든 괜찮지만 경로에 한글과 공백이 없는 곳을 권합니다. 이 문서에서는 D:\PRAP\ 로 적겠습니다.

D:\PRAP\                        ← 작업 폴더 (담당자 PC에만 존재)
  src\        45개    앱의 소스. 직접 고칠 일은 없습니다
  tools\      70개    빌드·검증 도구. 여기 있는 명령을 실행합니다
  templates\          ← 명령으로 생깁니다. 빈 서식과 예제 데이터
  docs\               계획서·사양서. 배포에는 필요 없습니다
  app\                웹 버전(PRAP.html). 이번 배포와는 무관합니다
  dist\               ← 빌드 산출물이 여기 생깁니다. 지워도 다시 만들어집니다
  _download\          ← 직접 만드십시오. 내려받은 파이썬 zip 을 여기 둡니다

PRAP_source_src_tools.zip 을 D:\PRAP\ 에 풀면 src\ 와 tools\ 가 생깁니다. templates\ 는 첫 명령이 만들어 주므로 따로 구하지 않아도 됩니다. docs\(계획서·사양서)는 배포에 필요하지 않으며, 문서를 다시 생성하실 때만 저장소에서 받으십시오.

1-3. 파이썬 두 가지를 구분해서 준비합니다

헷갈리기 쉬운 지점이라 표로 적습니다. 서로 다른 두 개이고, 둘 다 필요합니다.

무엇어디에어떻게쓰임
담당자 PC의 파이썬 담당자 PC에 설치 python.org 설치 프로그램
또는 IT 배포		 아래 명령들을 실행하기 위한 것. 3.9 이상
배포용 런타임 D:\PRAP\_download\ Windows embeddable
package (64-bit) zip		 사용자 PC에 딸려 보낼 것. 설치하지 않고 파일로만 씁니다
받을 때 헷갈리기 쉬움

python.org/downloads/windows 한 페이지에 둘 다 있습니다.

Windows installer (64-bit) → 담당자 PC에 설치하는 것 (.exe)
Windows embeddable package (64-bit) → 배포에 쓸 것 (-embed-amd64.zip)

잘못 받으셔도 3단계 도구가 이름을 대며 거부하니 파일이 뒤섞일 일은 없습니다.

1-4. 확인

cd /d D:\PRAP
python --version

Python 3.9.x 이상이 나오면 됩니다.

2공유 폴더 준비 — 최초 1회

공유 폴더에 두 개를 만드십시오. 역할이 다르고 권한도 달라야 합니다.

\\서버\공유\PRAP\
  배포\      담당자가 만든 파일을 놓는 곳
  데이터\    사용자의 계획서가 사는 곳
폴더담당자사용자왜
배포\ 읽기 + 쓰기 읽기만 사용자가 실수로 배포본을 지우거나 덮어쓰지 못하게. 여기 파일이 훼손되면 전원이 영향을 받습니다
데이터\ 읽기 + 쓰기 읽기 + 쓰기 계획서를 저장해야 하므로. 쓰기 권한이 없으면 동시 편집 잠금이 아예 동작하지 않습니다
데이터 폴더는 비워 두십시오

빈 폴더 하나만 만들고 손대지 마십시오. 안의 구조(shared\, users\, audit\)는 앱이 처음 실행될 때 스스로 만듭니다. 미리 만들어 두면 이름이 어긋날 수 있습니다.

2-2. IT에 요청해 둘 것

  • 데이터\ 폴더 백업. 팀의 계획서가 전부 여기 있습니다. 앱은 이전 판본을 자동 보관하지만 그것도 같은 폴더 안에 있으므로, 폴더 자체가 사라지면 함께 사라집니다.
  • 사용자 그룹의 쓰기 권한. 위 표대로.

    가운데 네 줄은 방금 넣은 파이썬에게 직접 물어본 결과입니다(윈도우에서만 나옵니다). tkinter absent 는 정상입니다 — embeddable 파이썬에는 원래 없고, 앱은 그 경우 자기 화면에 폴더 선택창을 대신 띄웁니다. START 줄에 버전이 찍히면 그 파이썬으로 앱이 실제로 뜬다는 뜻입니다. 이때 앱이 실행되지는 않습니다 — --version 은 버전만 찍고 바로 끝나는 옵션입니다.

    맨 끝에 NOT READY TO HAND OUT 이 보이면

    점검 중 하나가 통과하지 못한 것입니다. 압축 파일은 그래도 만들어져 있습니다(그래서 잃은 것은 없습니다). 다만 그 줄이 가리키는 항목의 원인을 확인하기 전에는 배포하지 마십시오. 대개는 build_python_app.py 를 다시 돌리지 않아 앱 폴더가 낡았거나, 내려받은 zip 이 embeddable 판이 아닌 경우입니다.

    이 순서를 거꾸로 하지 마십시오

    build_python_app.py --zip 으로 압축하면 먼저 다시 빌드하면서 runtime\ 을 지웁니다. 그렇게 만든 압축본에는 런타임이 없고, 담당자 PC에서는 잘 돌기 때문에 알아채기 어렵습니다 — 파이썬이 없는 사용자 앞에서만 실패합니다.

    파일 이름으로 구분하십시오. _with_runtime 이 들어간 것이 나눠 줄 파일입니다.

5새 버전을 낼 때

3장을 다시 하고, 사용자에게는 이렇게 안내하십시오.

  1. 새 압축본을 자기 PC로 복사

    배포\ 에서 새 _with_runtime.zip 을 받습니다.

  2. 새 폴더에 풀기

    기존 PM_APP\ 위에 덮어쓰지 말고 PM_APP_new\ 같은 새 폴더에 푸십시오.

  3. 이전 폴더의 data\ 를 새 폴더로 옮기기

    팀 공유만 쓰신 분은 이 단계가 필요 없습니다 — 계획서가 공유 폴더에 있기 때문입니다. 개인 계획서를 data\ 에 두신 분만 해당합니다.

  4. 이전 폴더 삭제, 새 폴더 이름을 PM_APP 으로

    바로가기를 만들어 쓰셨다면 바로가기의 대상 경로를 확인하십시오.

사용자에게 반드시 전할 것

기존 폴더를 통째로 지우고 새로 푸는 방식은 위험합니다. 개인 계획서가 data\ 에 있으면 함께 사라집니다. 새 폴더에 풀고 data\ 를 옮기는 순서를 지키게 하십시오.

7주의사항

앱 폴더를 공유 폴더에 두고 실행하게 하지 마십시오

실측으로 확인된 것은 "사용자 폴더에서 실행 허용" 이고, 네트워크 경로(UNC)에서 실행파일을 돌리는 것은 별개의 통제라 막혀 있는 경우가 흔합니다. 앱은 각자 PC, 계획서만 공유 폴더 형태를 유지하십시오.

다시 빌드하면 runtime\ 이 사라집니다

build_python_app.py 는 dist\PM_APP_py\ 를 비우고 다시 만듭니다. 빌드가 화면으로 알려 주지만, 빌드 → 번들 → 압축 순서를 기억해 두십시오.

배포본 안의 이름은 신원 확인이 아닙니다

사용자가 처음에 입력하는 이름·부서는 동료에게 보여 주기 위한 것이고 로그인이 아닙니다. 누가 무엇을 했는지의 증거로 쓰지 마십시오. 파일은 이름이 아니라 윈도우 계정 기준으로 나뉩니다.

아직 확인되지 않은 것

모든 검증은 리눅스에서 이루어졌습니다. 윈도우 공유 폴더에서의 동작은 check_share.py 가 현장에서 답합니다 — 2-1 단계를 건너뛰지 마십시오. 그것이 리눅스에서 증명할 수 없는 부분을 실제 환경에서 재는 유일한 방법입니다.

이 문서의 경로·명령·화면 출력·폴더 구조는 모두 PM_APP 1.21.1 을 실제로 실행해 얻은 것입니다. 버전이 올라가면 version.txt 와 압축본 이름이 달라집니다. 사용자용 안내서는 별도 문서입니다.
