1.22에서 달라진 것

마일스톤에 색을 표시할 수 있습니다. 마일스톤 표의 날짜 옆 칸에서 색을 고르면 Project timeline에서 그 마일스톤만 그 색으로 그려집니다 — 실사, 밀린 날짜처럼 눈에 띄어야 하는 것을 위한 기능입니다. 색 목록은 서식의 Lists 시트에 있어 팀이 직접 바꿀 수 있습니다.

기존 계획서는 그대로 열립니다. 색 칸이 없을 뿐이고, 숫자는 하나도 달라지지 않습니다.

먼저 큰 그림 하나만. 이 앱은 각자 PC에서 돌고, 계획서 파일만 공유 폴더에 둡니다. 프로그램을 공유 폴더에 놓고 거기서 실행하는 방식이 아닙니다 — 그 이유는 아래 주의사항에 있습니다.

그리고 파이썬은 따로 손댈 일이 없습니다. 파이썬 런타임은 나눠 드리는 압축본 안에 이미 들어 있습니다. 사용자는 압축을 한 번 풀 뿐, 파이썬을 내려받지도 설치하지도 않습니다 — 내려받는 것은 준비 담당자가 딱 한 번입니다.

누가 무엇을 하는가

역할 A 준비 담당자

파이썬이 있는 PC에서 배포용 압축본을 한 번 만들고, 공유 폴더를 준비합니다. 이후 새 버전이 나올 때만 다시 합니다.

버전마다 한 번 · 15분
역할 B 일반 사용자

압축본을 자기 PC로 복사해 풀고 더블클릭합니다. 설치도, 설정도, 관리자 권한도 없습니다.

각자 한 번 · 2~3분

팀과 함께\\서버\공유\PRAP\데이터\됩니다 — 한 번에 한 사람이 편집, 나머지는 열람바로가기 한 줄 (아래 B-5)

팀과 함께 쓰실 계획이면 공유 폴더 경로를 먼저 정해 두십시오. 아래 절차에서 계속 쓰입니다. 이 안내서에서는 \\서버\공유\PRAP\ 로 적겠습니다.

A. 준비 담당자 — 버전마다 한 번

파이썬이 설치된 PC에서 합니다. 개발용 PC든 담당자 PC든 상관없습니다.

  1. 파이썬 런타임 내려받기

    python.org/downloads/windows 에서 Windows embeddable package (64-bit) 를 받으십시오. 파일 이름이 -embed-amd64.zip 으로 끝나는 것입니다.

    헷갈리기 쉬운 지점

    같은 페이지의 Windows installer (64-bit) 는 다른 물건입니다 — 그것은 설치 프로그램이고, 우리가 피하려는 바로 그것입니다. 잘못 받으셔도 다음 단계에서 도구가 이름을 대며 거부하니 안심하십시오.

  2. 앱 빌드하기 
    python tools\build_python_app.py

    dist\PM_APP_py\ 폴더가 만들어집니다.

  3. 런타임을 앱 폴더에 넣고 압축본 만들기 
    python tools\bundle_runtime.py python-3.13.15-embed-amd64.zip --zip

    dist\PM_APP_python_v1.22_with_runtime.zip 이 만들어집니다. 이것이 나눠 주실 파일입니다.

    파이썬 압축을 푸는 일은 여기서 끝납니다. 이 명령이 1번에서 받은 zip 을 앱 폴더 안 runtime\ 으로 풀어 넣고, 그 상태를 통째로 다시 압축합니다. 사용자 PC에서는 파이썬을 다시 풀 일이 없습니다.

    이 순서를 반드시 지키십시오

    build_python_app.py --zip 으로 압축하지 마십시오. 그 명령은 먼저 다시 빌드하는데, 다시 빌드하면 앱 폴더가 비워지면서 런타임도 함께 지워집니다. 그렇게 만든 압축본에는 런타임이 없고, 아무 경고도 없습니다.

    그래서 압축 기능을 bundle_runtime.py 쪽에 두었고, 파일 이름도 _with_runtime 으로 구분됩니다. 이름에 _with_runtime 이 있는 것을 나눠 주십시오.

  4. 공유 폴더 두 개 만들기 
    \\서버\공유\PRAP\
  배포\      ← 3번에서 만든 zip 을 여기 둡니다
  데이터\    ← 계획서가 사는 곳. 비워 두십시오. 앱이 알아서 채웁니다

    데이터 폴더는 직접 만들지 마십시오 — 빈 폴더 하나만 만들고 두십시오. 안의 구조는 앱이 처음 실행될 때 스스로 만듭니다.

  5. 공유 폴더가 쓸 만한지 확인하기 (권장) 
    python tools\check_share.py \\서버\공유\PRAP\데이터

    파일을 만들지 않고 화면에 열두 줄로 답합니다. 동시 편집 잠금, 저장 중 끼어듦, 변경 이력 이어쓰기가 이 공유 폴더에서 제대로 동작하는지 봅니다.

      writable (probe file)      PASS
  exclusive create           PASS      1 winner of 8 attempts
  rename over existing       PASS
  append, 2 writers          PASS      400 rows, 0 torn
  journal survives           PASS
  verdict                    SAFE FOR SHARED USE
  cleanup                    nothing left behind

    verdict 가 SAFE FOR SHARED USE 가 아니면 그 폴더를 팀 공유에 쓰지 마십시오. FAIL 줄을 알려 주시면 원인을 찾아 드리겠습니다.

B. 일반 사용자 — 각자 한 번

  1. 압축본을 내 PC로 복사

    \\서버\공유\PRAP\배포\ 에서 PM_APP_python_v1.22_with_runtime.zip 을 자기 PC로 복사하십시오.

  2. 압축 풀기

    내 문서 아래가 가장 좋습니다. 예를 들어 이렇게 됩니다.

    C:\Users\<내계정>\Documents\PM_APP\
  PM_APP.cmd          ← 실행할 파일
  PM_APP.py
  check_pc.py
  READ ME FIRST.txt
  version.txt
  app\
  pmapp\
  runtime\            ← 파이썬이 들어 있는 폴더. 지우지 마십시오
    파이썬 런타임은 따로 풀지 않습니다

    runtime\ 은 이 압축본 안에 이미 들어 있습니다. 파이썬을 따로 내려받거나, 따로 압축을 풀거나, 어딘가에 설치할 일이 없습니다. 압축을 한 번 풀면 제자리에 들어갑니다.

    앱이 찾는 위치는 PM_APP.cmd 와 같은 폴더 안의 runtime\ 딱 한 곳입니다. 위 그림의 모양 그대로 두시면 됩니다 — 폴더 안의 구조를 바꾸지 마십시오.

    바탕화면·다운로드 폴더는 피하십시오

    회사 PC는 바탕화면과 다운로드 폴더를 정리하거나 동기화하는 경우가 있고, 그러면 data\ 안의 작업이 함께 사라질 수 있습니다.

  3. 이 PC가 돌릴 수 있는지 확인 (선택) 
    runtime\python.exe check_pc.py

    열두 줄로 답합니다. verdict 가 YES 면 다음으로 가십시오. 파일을 만들지 않고, 경로·계정·기계 이름도 출력하지 않으므로 결과를 그대로 말씀해 주셔도 됩니다.

  4. PM_APP.cmd 더블클릭

    검은 창이 뜨고 브라우저가 열립니다. 창에는 이렇게 나옵니다.

      version      1.22
  application  C:\Users\...\Documents\PM_APP
  your data    C:\Users\...\Documents\PM_APP\data\users\<내계정>
  chosen by    3 - writable data\ beside the application
  listening    127.0.0.1:34769  (this machine only)

    your data 가 내 계획서가 저장되는 곳이고, chosen by 는 앱이 왜 그곳을 골랐는지입니다. 나중에 문제가 생기면 이 두 줄이 답을 갖고 있습니다.

    검은 창은 닫지 마십시오

    그 창이 프로그램 본체입니다. 닫으면 앱이 멈춥니다 — 그것이 정상적인 종료 방법이기도 합니다. 브라우저 탭만 닫아도 몇 초 뒤 함께 멈춥니다. 새로고침은 괜찮습니다.

    처음 한 번 이름과 부서를 묻습니다. 이것은 동료가 "누가 편집 중인지" 볼 때 쓰는 이름입니다.

  5. 팀과 함께 쓰려면 — 바로가기 하나 (팀 공유를 쓸 때만)

    PM_APP.cmd 를 오른쪽 클릭 → 바로 가기 만들기 → 만들어진 바로가기를 오른쪽 클릭 → 속성 → 대상 칸 끝에 공유 폴더를 덧붙이십시오.

    "C:\Users\<내계정>\Documents\PM_APP\PM_APP.cmd" "--data=\\서버\공유\PRAP\데이터"

    따옴표까지 그대로 넣으십시오. 경로에 공백이 있어도 이 형태면 동작합니다. 이제 그 바로가기로 실행하면 팀 폴더를 쓰고, 창에 이렇게 나옵니다.

      your data    \\서버\공유\PRAP\데이터\users\<내계정>
  chosen by    1 - the --data argument

    담당자가 대신 만들어 배포해도 됩니다. 아래 한 줄을 메모장에 붙여 PM_APP_팀.cmd 로 앱 폴더에 저장하면, 사용자는 그것만 더블클릭하면 됩니다.

    @echo off
"%~dp0PM_APP.cmd" "--data=\\서버\공유\PRAP\데이터"

계획서는 어디에 저장되는가

팀 공유로 실행했을 때 공유 폴더가 실제로 이렇게 됩니다. 사람이 만드는 것이 아니라 앱이 스스로 만든 구조입니다.

\\서버\공유\PRAP\데이터\
  shared\                          ← 팀이 함께 보는 계획서
    workspaces\
      팀계획.prap
    backups\
    READ ME - shared plans.txt
  users\
    kim\                           ← 각자의 개인 공간
      workspaces\
        kim-개인계획.prap
      backups\
      settings.json
    lee\
      workspaces\
        lee-개인계획.prap
      backups\
      settings.json
  audit\                           ← 변경 이력 (설치 전체에 하나)

앱 안에서 파일을 열거나 저장할 때 My plans / Team plans 두 칸이 보입니다. 팀이 함께 볼 계획서는 Team plans 에 두십시오. 개인 폴더는 다른 사람이 열 수 없어서, 거기 둔 계획서는 동시 편집 보호가 아예 작동하지 않습니다.

앱이 알아서 잡아 줍니다

개인 폴더에 있는 계획서를 다른 사람이 저장한 흔적이 있으면(= 손으로 복사해 온 것), 앱이 한 줄로 알려 주고 「팀 폴더로 옮기기」 버튼을 내어 줍니다. 계획서와 이전 판본까지 함께 옮겨집니다.

주의사항

하지 마십시오 — 공유 폴더에서 직접 실행

\\서버\공유\...\PM_APP.cmd 를 공유 폴더에 두고 거기서 바로 실행하는 방식은 권하지 않습니다. 실측으로 확인된 것은 "사용자 폴더에서 실행 허용" 이고, 네트워크 경로(UNC)에서 실행파일을 돌리는 것은 별개의 통제라 막혀 있는 경우가 흔합니다.

앱은 각자 PC, 계획서만 공유 폴더 — 이 형태가 이미 허용으로 확인된 상황과 정확히 같습니다.

하지 마십시오 — 새 버전을 덮어쓸 때 data\ 까지

새 버전을 받으면 앱 폴더의 내용만 교체하십시오. data\ 폴더는 그대로 두셔야 합니다 — 배포 압축본에는 들어 있지 않으니, 폴더를 통째로 지우고 다시 푸는 방식만 피하시면 됩니다.

안전한 방법: 압축을 새 폴더에 풀고, 이전 폴더의 data\ 를 새 폴더로 옮기십시오.

담당자용 — 다시 빌드하면 런타임이 사라집니다

build_python_app.py 를 다시 돌리면 앱 폴더가 비워지고 runtime\ 도 함께 지워집니다. 빌드가 그 사실을 화면에 알려 주지만, 빌드 → 번들 → 압축 순서를 기억해 두시는 편이 낫습니다.

알아 두실 것 — 이름은 신원 확인이 아닙니다

처음에 입력하는 이름과 부서는 동료에게 보여 주기 위한 것이지 로그인이 아닙니다. 누가 무엇을 했는지에 대한 증거로 쓰지 마십시오. 파일이 저장되는 폴더는 이름이 아니라 윈도우 계정 기준으로 나뉩니다.

같은 이름의 계획서

팀 폴더에 이미 같은 이름의 계획서가 있으면 옮기기가 거부됩니다. 남의 작업을 덮어쓰지 않기 위해서입니다. 내 것의 이름을 바꾸시거나, 상대의 것을 먼저 열어 같은 계획서가 두 벌인 것은 아닌지 확인하십시오.

문제가 생기면

증상원인조치
검은 창이 번쩍 뜨고 사라짐 앱이 시작에 실패했고 메시지가 창과 함께 사라짐 정상이라면 창이 멈춰 서서 이유를 보여 줍니다. 그래도 사라지면 runtime\python.exe check_pc.py 를 돌려 보십시오
This PC has no Python... runtime\ 이 없는 압축본을 받으신 것 담당자에게 이름에 _with_runtime 이 있는 압축본을 요청하십시오
파이썬을 어디에 풀어야 하는지 모르겠음 풀 필요가 없습니다 — 압축본 안에 이미 들어 있습니다 앱 폴더 안에 runtime\ 이 보이면 된 것입니다. 없다면 이름에 _with_runtime 이 없는 압축본을 받으신 것입니다
브라우저가 안 열림 기본 브라우저가 등록되어 있지 않음 앱은 정상 동작 중입니다. 검은 창의 http://127.0.0.1:... 주소를 복사해 브라우저에 붙여 넣으십시오
팀 계획서가 안 보임 공유 폴더를 지정하지 않고 실행한 것 창의 chosen by 줄을 보십시오. 1 - the --data argument 가 아니면 B-5의 바로가기로 실행하고 계신 것이 아닙니다
읽기 전용 — OOO님이 편집 중 정상입니다. 한 번에 한 사람만 편집합니다 기다리시면 됩니다. 상대가 끝내면 30초 안에 앱이 알려 줍니다 — 다시 열 필요 없습니다
somebody else saved this plan... 내가 연 뒤에 동료가 저장했습니다. 저장은 거부되었고 동료의 작업은 무사합니다 File → Reload plan 으로 최신 내용을 불러온 뒤 다시 수정하십시오
Microsoft Store 가 열림 PM_APP.py 를 직접 실행하셨을 때 생길 수 있습니다 PM_APP.cmd 로 실행하십시오. 그쪽은 이 현상을 피하도록 되어 있습니다

지울 때

폴더를 지우면 끝입니다. 레지스트리에 남는 것도, PATH에 더해진 것도, 시작 프로그램에 등록된 것도 없습니다. 공유 폴더의 계획서는 그대로 남습니다.

이 안내서의 경로·화면 출력·폴더 구조는 모두 PM_APP 1.22 을 실제로 실행해 얻은 것입니다. 버전이 올라가면 version.txt 와 압축본 이름이 달라집니다.
