# 05. 정보 구조와 화면 개념

## 1. 설계 원칙

화면 설계에서 지킬 세 가지입니다.

**첫째, 계층별로 다른 화면을 만듭니다.** [02](02-personas-and-use-cases.md) 1장에서 정리한 L1/L2/L3 계층은 필요한 정보의 양이 다릅니다. 같은 화면을 요약만 바꿔 제공하는 방식은 세 계층 모두를 불만족시킵니다.

**둘째, 모든 숫자에서 근거까지 내려갈 수 있어야 합니다.** 집계 숫자를 클릭하면 그 숫자를 구성하는 개별 행 목록으로 이동합니다. 예외 없이 적용합니다.

**셋째, 화면마다 스냅샷과 가정 버전을 표시합니다.** 이것이 빠지면 재현 가능성 원칙([03](03-core-concept-model.md) 7장)이 무너집니다.

```
   │  ├─ Data Drops                  업로드 이력, 스냅샷 관리

```

## 3. 화면별 개념

### 3.1 Portfolio (L3 — 관리자·경영층)

여러 시험을 한 줄씩 보여줍니다. **정상인 것은 강조하지 않고 문제만 드러내는 것**이 설계 목표입니다.

```
┌──────────────────────────────────────────────────────────────────────┐
│  Portfolio                        스냅샷: 2026-09-14 08:00           │
├──────────────────────────────────────────────────────────────────────┤
│  시험        단계      EDC    Sample  Image   SDV    Timeline  위험  │
│  ─────────────────────────────────────────────────────────────────   │
│  ABC-301     Enroll    ●      ●       ●       ●      ●        —      │
│  ABC-302     Enroll    ●      ▲       ●       ▲      ●        2      │
│  XYZ-201     DBL 준비  ▲      ●       ●       ●      ✕        3      │
│              └ DBL 마일스톤 2주 초과 예상 · investigator sign 41%    │
└──────────────────────────────────────────────────────────────────────┘
```

위험 열의 숫자는 미해결 위험 신호의 건수입니다. 문제가 있는 행에만 한 줄 요약이 붙습니다.

### 3.2 Trial Overview (L2 — 시험 리드)

한 시험의 6개 도메인을 한 화면에 요약합니다. 각 카드는 해당 도메인 화면으로 연결됩니다.

구성 요소는 다음과 같습니다.

| 영역 | 내용 |
|---|---|
| 헤더 | 시험명, 단계, 스냅샷 시각, 가정 버전, 필터(국가·사이트) |
| 위험 신호 | 임계값을 벗어난 지표 목록. 클릭하면 원인 화면으로 이동 |
| D1 카드 | 입력을 뿌리로 한 5갈래 병행 진척 막대 + 미서명 건수 ([04](04-domain-concepts.md) 1.8) |
| D2 카드 | 등록 추이, 윈도우 이탈·미수행 건수 |
| D3 카드 | 다음 4주 SDV 방문 계획과 적정성 판정 |
| D4/D5 카드 | 단계별 정체 건수 |
| D6 카드 | 다음 3개 마일스톤과 예상 달성 여부 |

### 3.3 도메인 화면 공통 레이아웃

여섯 도메인 화면은 **동일한 레이아웃**을 사용합니다. [03](03-core-concept-model.md)에서 개념을 통일했기 때문에 화면도 통일할 수 있고, 이것이 학습 비용을 크게 낮춥니다.

```
┌───────────────────────────────────────────────────────────────────┐
│ [도메인명]   스냅샷 ▾  가정 v3 ▾  설정 v2 ▾  지표정의 v1 ▾        │
│                                                                   │
│ 분모 기준:  [● Due]  [ Protocol ]  [ Forecast ▸ 기준일 ]          │
├───────────────────────────────────────────────────────────────────┤
│ 필터:  국가 ▾   사이트 ▾   피험자 ▾   기간 ▾   [저장된 뷰 ▾]     │
├───────────────────────────────────────────────────────────────────┤
│ ① 단계별 요약 (KPI 타일 + 단계 막대)                             │
│    예외(WAIVED) 84건 · 분모 제외됨  [상세]                        │
├───────────────────────────────────────────────────────────────────┤
│ ② 롤업 테이블                                                     │
│    레벨 전환: [Trial] [Country] [Site] [Subject]                  │
│    열: due · 완료 · backlog · rate · 기한초과 · 예외              │
├───────────────────────────────────────────────────────────────────┤
│ ③ 드릴다운 패널 — 행 클릭 시 개별 항목 목록                       │
│    각 행은 항목 1건. 현재 단계, due date, 경과일, 이슈·예외 여부   │
│                                              [CSV/Excel Export]   │
└───────────────────────────────────────────────────────────────────┘
```

여기서 ①②③의 관계가 원칙 2(근거까지 드릴다운)를 구현합니다. ②의 어느 칸을 클릭하든 ③에는 **정확히 그 칸을 구성하는 항목들**이 나타납니다.

#### 분모 기준 토글

[03](03-core-concept-model.md) 3.4에서 확정된 세 기준을 사용자가 전환합니다. **세 값은 모두 미리 계산되어 있으므로 전환은 즉시 반응하며 재계산을 유발하지 않습니다.**

| 기준 | 선택 시 |
|---|---|
| `Due` (기본) | 지금 나와야 하는 것 대비 진척. 정상 상태 목표 100% |
| `Protocol` | 시험 전체 예상 대비 진척. 총량 감각 |
| `Forecast` | 지정 기준일까지 예상되는 양 대비. 기준일 선택 UI가 함께 나타남 |

토글 선택은 저장된 뷰에 포함되며, export 시에는 **세 값이 모두 별도 컬럼으로** 내보내집니다.

#### 예외(WAIVED) 표시

예외 항목은 분모에서 빠지므로 화면에서 **사라지지 않고 병기**됩니다. 분모가 조용히 줄어드는 것이 가장 위험하기 때문입니다. 건수를 클릭하면 `waiver_type`별 분해와 사유 목록이 나타납니다.

#### 단계가 꺼져 있는 경우

`trial_config`에서 꺼진 단계는 0%로 표시되지 않고 **화면에서 제외**되며, 설정 영역에 "이 시험은 data review를 적용하지 않음"처럼 사유가 표시됩니다 ([04](04-domain-concepts.md) 1.4).

### 3.4 Subject 360 (L1 — 실무)

한 피험자에 대한 모든 도메인 정보를 시간 축으로 보여줍니다. 실무자가 "이 피험자 왜 이래?"에 답하는 화면입니다.

```
┌──────────────────────────────────────────────────────────────────────┐
│ Subject 1023-007  |  Site 1023 (Korea)  |  Randomized 2026-02-14     │
│ 상태: On treatment   층화: [마스킹됨]    마지막 방문: V5 (2026-08-20)│
├──────────────────────────────────────────────────────────────────────┤
│         V1    V2    V3    V4    V5    V6(예정 09-18)   V7            │
│ 방문    ✓     ✓     ✓     ✓+3   ✓     ○                ○            │
│ 폼입력  ✓     ✓     ✓     ✓     ▲3    -                -            │
│ SDV     ✓     ✓     ▲     ✕     ✕     -                -            │
│ 샘플    ✓     ✓     ✓     ⊗1    ▲2    -                -            │
│ 영상    ✓     -     ✓     -     ▲     -                -            │
│ 쿼리    -     1     -     2 open -     -                -            │
├──────────────────────────────────────────────────────────────────────┤
│ ⚠ V4 방문이 윈도우 +3일 초과                                        │
│ ⊗ V4 샘플 1건 분실 (central lab 배송 중) — 데이터 대조 필요          │
└──────────────────────────────────────────────────────────────────────┘
```

이 화면 하나가 네 도메인을 가로지릅니다. 실무자가 가장 자주 쓸 화면이 될 가능성이 높습니다.

### 3.5 Reconciliation Center

[03](03-core-concept-model.md) 5장의 4종 불일치를 도메인에 관계없이 하나의 작업 목록으로 모읍니다. 각 항목은 담당자 배정, 코멘트, 해결 처리가 가능합니다.

| 탭 | 내용 |
|---|---|
| Expected but not received | 나와야 하는데 안 온 것 |
| Received but not expected | 예상에 없는데 들어온 것 |
| Discrepant | 속성 불일치 |
| Ambiguous | 매칭 후보 다수 |

### 3.6 Data & Configuration

이 앱의 신뢰성을 담보하는 화면입니다.

**Data Drops.** 업로드 이력을 보여줍니다. 각 Drop마다 언제, 누가, 어떤 파일을, 어떤 template·매핑 버전으로 올렸고, 몇 건이 처리·거부·경고되었는지 표시합니다. 검증 리포트를 원본 행 번호와 함께 내려받을 수 있습니다. 특정 Drop 시점의 스냅샷으로 전체 화면을 되돌려볼 수 있습니다.

**Source Templates.** 표준 source dataset template을 내려받고, Mapping Profile을 설정합니다 ([12](12-standard-source-templates.md)). 매핑이 설정되면 사용자는 vendor 원본 리포트를 그대로 올릴 수 있습니다. 매칭 키 선언도 이 화면에서 관리하며, 입도가 권고에 미달하면 경고가 표시됩니다.

**Trial Configuration.** 유예 기간, 단계 on/off, partial SDV 범위, 쿼리 소유자별 기한, 대상 피험자 목록, 지표 on/off를 관리합니다 ([13](13-trial-configuration.md)). 버전 간 차이(diff)를 보여주고, 설정 변경이 지표에 미치는 영향을 **적용 전에 미리보기**로 제공합니다. 이것이 없으면 사용자가 설정 바꾸기를 두려워합니다.

**Assumption Sets.** SoA, 방문 스케줄, 등록 계획을 편집하고 버전으로 관리합니다.

**Metric Definitions.** 각 지표의 정의와 계산식을 열람합니다 ([15](15-metric-specification.md)). 벤치마크([01](01-benchmark.md) 2.2)에서 확인한 "정의 불일치가 최대 실패 원인"에 대한 대응입니다. 화면의 지표 이름 옆 `?` 아이콘에서 이 정의로 바로 연결됩니다.

### 3.7 Admin (P8 전용)

요구사항 C2가 명시한 별도 탭입니다. 사용자, 역할, 권한, 시험 배정, 감사 추적 조회를 담당합니다. 상세는 [08](08-platform-services.md) 2장에서 다룹니다.

감사 추적 조회 화면은 **행위자를 사람 / AI / 엔진으로 구분**해 표시하며, AI 행위는 어느 작업의 어느 실행 결과인지까지 추적됩니다 ([14](14-ai-extensibility.md) 5장). AI 활동 전용 화면에서는 실행 이력, 승인 대기 제안, 권한 정책에 의해 차단된 시도를 조회합니다.

## 4. 공통 상호작용 개념

### 4.1 저장된 뷰 (Saved View)

필터, 레벨, 정렬 조합을 이름 붙여 저장합니다. "내 담당 사이트의 SDV backlog"를 매번 다시 설정하지 않아도 되게 합니다. 팀 공유도 가능하게 합니다.

### 4.2 비교 모드

두 스냅샷을 선택해 지표 변화를 나란히 보여줍니다. UC-1(주간 리뷰)의 "지난주 91% → 이번 주 86%"가 이 기능입니다.

비교하는 두 스냅샷의 **설정 버전이나 지표 정의 버전이 다르면 경고가 표시**됩니다. 유예 기간이 바뀐 상태로 두 시점을 비교하면 변화의 원인이 실적인지 설정인지 구분할 수 없기 때문입니다.

### 4.3 Export 버튼의 위치

원칙 4.7(데이터를 가두지 않는다)에 따라 **모든 테이블에 export 버튼**을 둡니다. 예외를 두지 않습니다.

### 4.4 알림 (Notification)

임계값 초과, 신규 불일치 발생, 마일스톤 위험 전환 시 알림을 보냅니다. 초기에는 **이메일 요약**으로 충분하며, 앱 내 알림 센터는 후속 단계로 둡니다.
