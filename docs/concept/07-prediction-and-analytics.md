# 07. 예측과 분석

요구사항에서 "단순히 데이터 진척 확인뿐 아니라 다양한 예측과 추적으로 목적을 확장하고 싶다"고 하셨습니다. 이 문서는 그 확장의 개념을 정의합니다.

## 1. 예측의 세 계층

예측은 난이도와 신뢰도가 다른 세 계층으로 나뉩니다. 이 구분이 중요한 이유는 **낮은 계층부터 확실히 만들어야** 높은 계층이 의미를 갖기 때문입니다.

| 계층 | 성격 | 신뢰도 | 필요 데이터 |
|---|---|---|---|
| **결정론적 전개** | 규칙에 따라 계산 | 높음 | 프로토콜 + 현재 상태 |
| **추세 외삽** | 과거 속도를 미래로 연장 | 중간 | 수 주~수 개월 이력 |
| **통계·학습 모델** | 패턴 학습 | 낮음 (초기) | 다수 시험의 누적 이력 |

> **권고.** **결정론적 전개와 추세 외삽까지를 초기 범위로 합니다.** 통계 모델은 데이터가 쌓인 뒤 도입합니다. 이유는 명확합니다. 초기에는 학습할 이력이 없고, 근거 없는 예측은 사용자 신뢰를 한 번에 잃습니다. 신뢰를 잃은 예측 기능은 다시 켜지지 않습니다.

## 2. 결정론적 전개 (Layer 1)

### 2.1 방문 전개

등록된 피험자에 대해 남은 방문 일정을 계산합니다.

```
for 피험자 in 활성 피험자:
    anchor = 피험자.randomized_date (또는 시험 설정 기준일)
    for 방문 in 방문스케줄:
        if 방문.미발생:
            예상일 = anchor + 방문.offset_days
            윈도우 = [예상일 - before, 예상일 + after]
```

### 2.2 기대 항목 전개

예상 방문에 SoA를 적용해 미래에 발생할 폼·샘플·이미지를 계산합니다. 이것이 요구사항의 "expected"를 미래로 확장한 것입니다.

### 2.3 이 계층만으로 답할 수 있는 질문

- 다음 4주간 이 사이트에서 몇 건의 방문이 예정되어 있는가
- 이번 분기에 채취될 샘플은 몇 건인가
- 현재 등록된 피험자가 모두 완료하면 총 몇 건의 폼이 생기는가

이 질문들은 **가정만으로 정확히 답할 수 있으며 예측 오차가 없습니다.** 따라서 가장 먼저 제공합니다.

## 3. 추세 외삽 (Layer 2)

### 3.1 등록 예측

```
최근 N주 실제 등록 속도 → 사이트별 등록률 → 목표 등록 완료 시점 예측
```

신규 활성화 예정 사이트가 있으면 활성화 일정과 예상 등록률을 함께 반영합니다.

### 3.2 데이터 도착 지연 모델

이것이 이 앱 고유의 예측입니다. 사이트마다 **방문 후 데이터 입력까지 걸리는 시간 분포**가 다릅니다.

```
lag(site) = 분포(entered_at - visit_date)   # 중앙값, 90퍼센타일
```

이 분포를 알면 두 가지가 가능해집니다.

**첫째, 정상/이상 판별.** 어떤 사이트의 미입력 폼이 그 사이트의 평소 지연 범위 안이면 문제가 아닙니다. 90퍼센타일을 넘으면 문제입니다. 이것이 단순 backlog 건수보다 훨씬 나은 신호입니다.

**둘째, 도착 예측.** 현재 backlog가 각 사이트의 지연 분포에 따라 언제 해소되는지 계산할 수 있습니다.

### 3.3 Backlog 소진 예측 (Burn-down)

```
현재 backlog + 향후 유입(Layer 1 전개) - 처리 속도(최근 추세) → 소진 시점
```

이 계산이 UC-4(DBL 준비도 판단)의 근거이고, [04](04-domain-concepts.md) 6.5의 `AT_RISK` 마일스톤 판정의 근거입니다.

```
┌─────────────────────────────────────────────────────┐
│  SDV Backlog 소진 예측                              │
│                                                     │
│  3000 ┤ ●                                           │
│       │   ●                                         │
│  2000 ┤     ●  ╌╌╌ 현재 속도 유지 시                │
│       │       ●   ╌╌╌                               │
│  1000 ┤         ●     ╌╌╌                           │
│       │                   ╌╌╌                       │
│     0 ┼───────────────────────╌╌╌──────────         │
│       8월    9월    10월   11월  ↑         12월     │
│                             DBL 계획   예상 완료    │
│                                        (+3주 지연)  │
└─────────────────────────────────────────────────────┘
```

### 3.4 SDV 물량 예측

[04](04-domain-concepts.md) 3.3의 계획 적정성 평가를 뒷받침합니다.

```
방문시점_예상물량(site, T) = 현재_SDV_backlog(site)
                            + Σ(T까지 예상 방문 × SDV 대상 폼 수 × 입력 완료 확률)
```

## 4. 예측의 표현 규칙

예측 기능의 성패는 알고리즘보다 **표현 방식**에서 갈립니다. 세 가지 규칙을 정합니다.

### 4.1 점 추정 대신 구간

`11월 14일 완료` 대신 `11월 10일 ~ 11월 28일 (중앙값 11월 18일)`로 표시합니다.

### 4.2 근거를 항상 함께

예측값 옆에 사용된 가정을 한 줄로 표시합니다. 예: `최근 8주 처리 속도 기준, 신규 사이트 2곳 제외, 12월 공휴일 미반영`.

### 4.3 예측과 사실을 시각적으로 구분

실적은 실선, 예측은 점선으로 일관되게 구분합니다. 표에서는 예측값에 별도 표식을 답니다. 사용자가 두 가지를 혼동하는 순간 이 기능은 위험해집니다.

## 5. KRI / QTL — RBQM으로의 확장

벤치마크([01](01-benchmark.md) 1.3, 2.1)에서 확인했듯, ICH E6(R3)는 CtQ 요소를 KRI와 QTL로 연결해 중앙 모니터링하는 구조를 지향합니다. 이 앱이 만드는 지표는 그대로 KRI가 될 수 있습니다.

### 5.1 KRI 후보

| KRI | 도메인 | 신호하는 위험 |
|---|---|---|
| 데이터 입력 지연 (중앙값) | D1 | 사이트 운영 역량 |
| Overdue 쿼리 비율 | D1 | 사이트 응답성 |
| 방문 윈도우 이탈률 | D2 | 프로토콜 준수 |
| 샘플 분실·부적합률 | D4 | 검체 취급 품질 |
| 영상 QC 실패율 | D5 | 영상 획득 품질 |
| SDV 미실시 기간 | D3 | 모니터링 공백 |
| Reconciliation 미해결 건수 | 전체 | 데이터 무결성 |

### 5.2 QTL 개념

QTL은 시험 수준에서 미리 정한 허용 한계입니다. 예를 들어 "방문 윈도우 이탈률 5% 초과 시 조치"처럼 정의하고, 초과 시 기록과 조치가 따르게 합니다.

> **권고.** KRI/QTL 기능은 **Phase 3**에 둡니다. 다만 [06](06-logical-data-model.md)의 `MetricDefinition`에 임계값(threshold) 속성을 **지금 설계에 포함**시켜 두어, 나중에 기능만 켜면 되도록 합니다.

### 5.3 사이트 성과 스코어

여러 KRI를 가중 합산해 사이트별 종합 점수를 만들 수 있습니다. 이것은 유용하지만 **오용 위험**이 큽니다. 단일 점수는 맥락을 잃고 사이트 평가에 부당하게 쓰일 수 있습니다.

> **권고.** 종합 점수는 제공하되 **항상 구성 요소를 펼쳐볼 수 있게** 하고, 점수만 단독으로 export되지 않도록 합니다.

## 6. 예측 기능 로드맵

| Phase | 기능 | 계층 |
|---|---|---|
| 1 | 방문 전개, 기대 항목 전개 | Layer 1 |
| 2 | 등록 예측, backlog 소진 예측, 데이터 도착 지연 모델 | Layer 2 |
| 2 | SDV 계획 적정성 평가 | Layer 2 |
| 3 | KRI / QTL, 사이트 스코어 | Layer 2 |
| 4 | 통계 모델 (사이트 위험 예측, 이상 탐지) | Layer 3 |
