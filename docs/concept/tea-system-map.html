The organising idea

Three clocks, running at different speeds

Most of the confusion about this system comes from reading it as one long process. It is three, and they tick at different rates with different people involved. Nearly every question of the form “wait, when does that happen?” resolves once you know which clock a thing belongs to.

The one rule that explains the architecture. Every number and every verdict is computed by ordinary code. The language model never does arithmetic, never creates or deletes a finding, and never decides a response category. It writes explanations, reads free text, and offers a judgement where the guideline itself asks for one. That single split is why the same verdicts come out of a commercial API and a locally hosted model, and why validation stays tractable.
Clock one

Development process and its gates

The steps are strictly sequential because each one’s output is the next one’s input. The gates are where work stops until someone approves — they are the real schedule risk, not the build effort.

Source data to output data

Where the data comes from, and where it goes

The important shape here is the loop at the bottom. The agent reads an export and produces text; a person issues the query. Nothing the agent writes reaches the EDC on its own, which is what keeps it decision support rather than a system of record.

One responsibility never moves. The agent produces suspicions. A qualified person confirms every issue and issues every query. Findings are phrased as things to check, the confidence rate and determination mode are always on screen, and rejecting a finding takes one click — all of it designed to keep the reviewer’s judgement engaged rather than deferring to the machine.

If you read nothing else

Six things that decide whether this works

  • The deterministic split holds or it doesn’t. It is what makes local-model hosting, reproducibility and validation possible at once. Erode it and all three go.
  • Silence is a feature. A reviewer handed 400 findings reviews none. Deduplication, query reconciliation and confidence ranking are load-bearing, not polish.
  • Confidence must be calibrated, not asserted. A confidence rate people learn to distrust is worse than none, because it invites unread query issuing. It gets measured against actual acceptance.
  • Coverage has to be published. The danger is a reviewer assuming the agent checked something it never checked. Every run states what was not evaluated, and why.
  • The rule pack has to stay cheap to change. Adding a review point is a declarative change with its own tests. The moment it needs engine surgery, the catalog stops growing.
  • Query wording is not a detail. The logic is settled, but the text in a query is what a site actually reads. It is reviewed on its own, by people who talk to sites, before anything freezes.
